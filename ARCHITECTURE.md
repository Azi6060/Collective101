# Collective 101 architecture

The living roadmap is [PROJECT_STATUS.md](PROJECT_STATUS.md). This document records implementation decisions and their consequences.

## Decision: supplied files, specialist conversations and provider-aware context (4 November 2026)

`attachments.py` stores chat-owned raw blobs and validated metadata in SQLite. It extracts UTF-8/DOCX text without filesystem extraction and creates native Meta content blocks for images/PDF/audio. Attachment interpretation/transcription is an audited preprocessing stage before Distribution (or the explicitly selected specialist). Main mission inputs carry attributed source excerpts, not arbitrary host paths or untrusted policy. Dedicated Meta ASR uses the same connector key; browser recordings are normalized to supported WAV. Raw downloads require the existing session and are attachment/octet-stream; UI media uses authenticated blobs and raster/audio MIME types. Pending files can be removed; bound files cannot be rebound to another chat. Failed historical sources do not cause automatic paid replay on unrelated turns.

Direct conversations persist an immutable selected agent identity in console_chat_agents, use that agent definition and current thread, and enforce the reply-only advisory contract. They cannot schedule departments or acquire tools. Normal organization routing remains head-led. The agent UI shows concise duties/reporting rather than internal prompts/permission/debug state. The Effectiveness UI is removed while developer evaluation/history remains separate.

The conversation window is 3 MB and text request transport guard 4 MB. Meta's `/responses/input_tokens` measures large reconstructed requests; an 8,192-token format margin plus configured output reserve protects the 1,048,576-token window. Bounded local context fitting preserves the newest intent and attributed incomplete older-user excerpts, never mutating originals. Actual post-fitting history bytes/messages and measured tokens are persisted. Byte accounting is not presented as an exact tokenizer. Request phases and retries use high reasoning, 65,536 work tokens growing to the documented 131,072 ceiling, and 600-second default timeout with recovery up to 900.

A live website test exposed desktop-only browser checks and stale pending-execution head reports. Browser selectors now accept bounded viewport dimensions; execution runs before final head reconciliation and that reconciliation receives observed evidence. Runtime failed checks, task failures, missing permissions and independent acceptance continue to block delivery. Original failed runs remain recorded.

## Decision: unlimited spending with finite execution and auditable trials (4 November 2026)

Zero in financial allowance fields denotes unlimited aggregate API calls/admission units. New chats, department runs and evaluations use this default; existing chat ledgers were explicitly migrated without resetting usage. Positive allowances retain historical/test compatibility. The UI has no financial controls or sample-count ceiling. Request/context, sandbox/permission, per-step retry/tool and finite graph/repair bounds remain. A narrower removal of the redundant global 40-tool quota was approved after a broader legacy/execution-guard patch was rejected.

MeteredProvider reserves and records usage under a lock while network work occurs outside the lock. Four concurrent evaluation workers use own nested meters, avoiding shared-counter differences and double attribution. Legacy finite admission failures propagate their owning meter, stop scheduling and produce budget_exhausted; quality/infrastructure and human-pending terminal states are distinct. Stop drains already dispatched work. Head evaluation passes the current provider identity explicitly to employee/evidence lookup rather than rebinding the shared console organization. Frozen cases/roles/memory/request policy and the v2 harness fingerprint preserve provenance. Evaluation output does not train operational memory or fabricate human review.

## Decision: evaluated, bounded departmental execution (3 November 2026)

`effectiveness.py` adds additive evaluation run/trial/request/human-review tables and a single bounded evaluation worker, separate from the chat queue. `benchmarks.py` owns versioned case inputs, published criteria and independent deterministic graders. All identities appear in scorecards; only the representative cases currently provided can generate formal evidence. Runtime quality, provider errors, unavailable execution, human-pending work and fixture data stay distinct. Score groups are fingerprinted by provider/model/endpoint, role definitions, suite/harness and request settings; role and case snapshots preserve the tested inputs. Paired comparisons have equal per-trial admission ceilings within a shared batch meter and show actual usage. A stopped/restarted evaluation never silently resumes billable work. Confirmed UI starts, stopping and human reviews use the existing token/same-origin API protections.

New runtime tables store a per-run concurrency/memory policy. `runtime_core.run_dag` schedules dependency-ready trusted internal jobs in bounded waves, supplies immutable completed dependency snapshots and drains in-flight work before propagating a failed/pending-human boundary. The departmental engine separates begin/employee/report jobs, preserving head-only handoffs, own-department assignments, deterministic output paths, independent review and repair caps. Budget reservations stay transactional. Tool calls reserve a recorded dispatch under the database lock before action, closing a reproducible parallel cap race; interrupted dispatches cannot silently duplicate actions. Old runs default to serial and repairs inherit policy.

`learning.py` retains historical cards and adds structured proposed/reviewed/revoked/expiring lessons tied to the producing agent, model signature and source run. Only reviewed, relevant, unexpired lessons enter reference retrieval. Memory-disabled policy also removes memory-search grants. Evaluation memory arms share a frozen reviewed snapshot and do not train on their output. Existing Director improvement messages are surfaced as hypotheses, not accepted prompt edits or earned promotion. General prompt optimization and demonstrable held-out improvement remain separate work.

`execution_adapters.py` is a fixed-command boundary. The static browser runner uses the existing capability preview and opaque iframe, a fresh sandboxed Chromium context, local-origin request restrictions, bounded selectors/actions and Windows process-tree ownership. It gives agents observed interaction evidence without arbitrary navigation/host evaluation. Python/offline Node use fixed digest-pinned Docker profiles with explicit source-only staging and resource/authority limits. No image is pulled and no generated code falls back to a host interpreter. Current Docker absence blocks real container validation. Mission browser/runtime checks read persisted artifacts, hash inputs, cache results and override positive review on failure. The browser adapter is currently Windows-specific; general external browsing/build-dependent preview/hosting remain unavailable.

The legacy event engine is isolated in `legacy/runtime.py`; the public `runtime.py` facade preserves earlier imports and commands. The generic departmental engine is canonical. This is an incremental compatibility boundary with regression coverage, not a destructive schema/engine rewrite.

Meta structured responses now use documented schema-constrained JSON, while native legacy tools retain their wire protocol. Empty assistant answers are provider failures with usage; malformed text produces safe shape metadata and actionable contract feedback. The observed research failure had zero dispatched searches; the raw rejected answer was not saved, so its exact cause cannot be narrowed beyond pre-tool response parsing. [Meta JSON schema guidance](https://dev.meta.ai/docs/cookbook/structured-output), [Playwright browser sandbox option](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox), [Windows job ownership](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) and [Docker runtime controls](https://docs.docker.com/engine/containers/run/) document underlying mechanisms, not a certification of this application.

## Decision: local static preview and readable completions (3 November 2026)

`preview.py` manages a lazy loopback HTTP listener on an OS-assigned port distinct from the console. A same-origin, session-protected POST `/api/chats/{id}/preview` creates/reuses an unguessable chat capability URL, admitting only live-mode chats with saved HTML. The listener has no console APIs, credentials or filesystem routing. It reads the chat's merged saved artifacts through the console, preserves safe paths, allows only selected static text MIME types, bounds snapshots at 20 MiB and admits eight chat capabilities. Closing the console HTTP server also shuts the preview listener down. Links are process-local and expire on restart.

The preview shell opens in a new tab with no opener. It owns page selection, manual refresh, optional two-second revision polling and missing-page/connection feedback. Its iframe permits scripts without same-origin privileges. Artifact response CSP also enforces `sandbox allow-scripts`, including direct artifact navigation, with explicit local asset sources, blocked connections/frames/forms/base elements and restricted permissions. The shell uses only packaged trusted static assets. No arbitrary host code, dependency installation or deployment is performed. This is a browser static-content boundary, not a general OS/network/process resource sandbox; root-relative URLs and build-dependent/full-stack code remain unsupported. Policy is based on [CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox) and [iframe sandbox behavior](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

`presentation.py` supplies `display_content` only for assistant messages matching a recorded completion. It maps each retained run/revision to its own summary, uses the Director's optional validated `user_summary` on accepted results, strips fingerprints/audit prefixes for historical fallback and emits truthful runtime failure/partial-file summaries. Original transcript content and retrospective evidence remain unchanged. Only role/content history is sent to intake, so presentation fields do not alter the recorded model conversation. The UI renders display text safely and keeps the file hash in a collapsed source detail disclosure.

## Decision: explicit model provenance and budget-visible request recovery

Accepted 2 November 2026 after the user-reported grocery-site mission timed out then returned a truncated response. `provider.py` categorizes timeout/connection/HTTP/truncation/invalid-response errors, validates operator settings, and implements phase profiles through `request_options` and `complete_with_options`. Existing scripted providers retain `complete(messages)` compatibility. The Meta adapter sends `max_completion_tokens` plus explicit low/medium reasoning effort; partial results are rejected before parsing into artifacts.

`model_requests.py` supplies durable category-based retry accounting, bounded backoff and additive migrations for request options/error classification on intake and organizational calls. The harness and console own retry loops so every network attempt is persisted and separately admitted through `budgets.reserve(..., output_tokens=...)`. They retain valid usage from truncated/malformed responses; uncertain network calls keep reservations. The evaluation meter forwards the same options and cost bounds. Provider failures do not consume the separate invalid-agent-output allowance. Operator caps, mission caps and tool limits remain independent.

`ConnectorManager.model_configuration()` reports safe presence/source metadata and effective operator limits without decrypting a credential. Saved encrypted credentials take precedence over `MODEL_API_KEY` in the server environment; explicit disconnect prevents fallback. Optional `model_options` in saved settings override environment/default request limits. The UI exposes model, endpoint host, credential/settings sources and request controls, and distinguishes presence from a verified connection. An environment source does not identify a secrets-manager extension. New schema columns preserve existing call/connector records; old failed missions are never relaunched automatically.

## Decision: leadership-only interdepartmental communication

The Mission Director works through heads. Employees send results only to their head and receive assignments only from that head. Heads communicate with heads and the director. LeadershipBus enforces these edges in code and records each handoff with sender, recipient, kind and content. It rejects cross-department employee messages, employee-to-director bypass, and direct colleague conversations, including within a department. This keeps the first implementation's collaboration explicitly head-mediated.

The council passes leadership-authored proposals. A head collects employee outputs and forwards a department report plus published artifacts. The Assurance head delegates an independent review to an employee who did not produce any mission artifact. Review results return through the Assurance head to the director. Employees are not given a global conversation inbox.

## Department-led lifecycle

`ready -> running -> reviewed | blocked`

1. Validate a generic mission contract: objective, inputs, constraints, acceptance criteria, allowed capabilities and optional deterministic artifact checks.
2. Intake supplies a department shortlist (legacy JSON without one defaults to all heads). Ask those heads and transitively requested dependency heads whether they can contribute; require a justified contribution or decline. A contributing head proposes up to six owned tasks, employee assignments, required capabilities, output paths and dependencies.
3. Run one council round. Heads see peer proposals and revise or retain their scope to avoid duplication and declare dependencies.
4. The director selects a useful dependency-closed subset. Validate both department and intra-department DAGs.
5. Execute selected departments in dependency order. Heads brief their employees; each employee receives its task, own task dependencies and head-forwarded upstream reports.
6. The drafting harness invokes each assigned employee. It validates exact declared output files, records artifact provenance and hashes, and returns results to the head. Missing capabilities or blocked dependencies produce explicit blocked outcomes.
7. Heads aggregate progress, blockers and improvement ideas and publish reports to other participating heads and the director.
8. The Assurance head chooses an independent reviewer. Require explicit coverage of every original acceptance criterion. Run deterministic file existence/substring checks separately; a positive model verdict cannot override their failures or runtime blockers.
9. The director synthesizes the outcome and proposes bounded improvements with a responsible department, supporting observation and measurement. Proposals are recorded and routed to heads; they are not auto-applied policy changes.
10. Store recent reviewed agent episodes for later same-agent, same-provider recall. Fixture and live memories cannot mix through this path.

Chat consults only shortlisted/dependency heads. Each consulted head has an assessment and council turn; a council request for an unconsulted department fails explicitly rather than silently widening the team. Legacy JSON without a shortlist retains all-head consultation. Department execution is sequential; no efficiency or scalability claim follows from this design.

## Harness capability boundary

`draft_artifact`, scoped knowledge/memory tools, configured public web search and optional `javascript_sandbox` are installed in the departmental path. It accepts model-produced bounded text/code files; drafting itself does not execute source; explicitly declared JavaScript acceptance checks use the separate WebAssembly adapter. Outputs stay in the database until explicit export to an isolated run folder. Paths must be normalized relative paths, must avoid Windows reserved names, and cannot collide by case or file/directory prefix. Export checks resolved containment and refuses to overwrite differing existing files.

Model instructions describe unavailable operations explicitly: no host shell, deployment, external messages, plugin installation or MCP connection. Public web search is available through the scoped adapter with configured credentials and frozen mission/task permissions. Human questions are agent-authored; there is no exact-query approval gate. A missing capability is an observable blocked state, not an implied grant. A future execution adapter can replace or extend this harness while preserving heads, ownership, validation and evidence. Neither the downloaded development skills nor the old event tools are wired into this new execution capability.

`reviewed` refers to artifact review plus any explicitly recorded sandbox checks. Only recorded org_executions or successful JavaScript org_tool_calls establish execution; the status alone cannot establish executed tests, deployment, external truth or usefulness on real missions. Free-form criteria receive model review; file checks provide only a narrow deterministic oracle.

## Persistence, resources and recovery

The original Store provides SQLite transactions. New `org_runs`, `org_calls`, `org_messages`, `org_artifacts`, and `org_experience` tables are additive and do not migrate or overwrite original event missions.

A run snapshots the mission and all agent definitions. Provider mode, model and endpoint must match on resume. Every phase reserves a call atomically, records its inputs, and validates its JSON response before caching it. Cached results are reused only when the agent/context hash matches. A phase has at most two failed/intervention attempts and four tool requests within an eight-call loop bound. A shared org_budgets record charges intake and mission provider requests before dispatch. UTF-8 input bytes plus a 4096 output allowance are charged as conservative token admission units. Failed/uncertain requests keep their reservation; provider-reported usage is recorded separately. No exact tokenizer or monetary billing ceiling is claimed.

CLI commands share the existing workspace lock. This is a single-process design; calling the library concurrently outside the CLI is not a supported scheduler. A process interruption between a provider response and its local commit may repeat that request on resume. No exactly-once provider guarantee is claimed. Source-code changes are not frozen with runs; only agent definitions and context are.

Message keys make leadership handoffs immutable on replay. Artifacts keep producer, task, path, content and SHA-256. Completed reviewed missions return without additional calls. Blocked results remain inspectable; resume reuses cached phases and does not invent new scope or refill exhausted attempts. General revisions and reviewer-driven rework rounds are future work.

Memory ranks up to 100 prior reviewed records for the same agent/provider by lexical overlap with the mission and task, with recency as a tie-breaker; it supplies at most three. An explicit memory_search tool can query these episodes. Per-step memories are frozen from the first recorded input when resuming. Approved long-term reference files live under knowledge/shared and knowledge/<department>, accessed only through scoped read/search tools. Its content is untrusted historical context, not a policy update. Retrospectives are improvement hypotheses, not measured learning or automatic responsibility changes.

## Implemented console and intervention boundaries

`web_server.py` serves a Bootstrap 5.3.8 UI and a small JSON API from loopback. Static routes are allowlisted; generated artifacts are returned as JSON/text, never served as executable pages. Host checks, per-process session tokens, same-origin mutation checks, request-size limits and CSP protect the local control surface. No credential values are sent to the browser.

`console.py` persists chats and intake rounds separately from mission execution. One background worker runs the organization; HTTP threads remain responsive for status and clarification answers. POST /api/chats uses a stable request_id to avoid duplicate submission; repeated keys with changed input are rejected. GET /api/organization lists definitions; GET /api/chats lists chats; GET /api/chats/{id} returns state/questions/brief; GET /api/activity/{run_id} returns recorded actions, handoffs, artifacts and executions. POST /api/chats/{id}/answers resolves a pending question; POST /api/chats/{id}/control pauses or resumes. Errors use JSON with an error string and an appropriate HTTP status.

The frontend renders runtime content with textContent. Artifact downloads use text blobs. The activity view exposes returned outputs, actions and observed evidence, not private model reasoning. Polling refreshes every 1.5 seconds; per-agent filters and expandable records make the history inspectable. Responsive desktop/mobile flows receive isolated Playwright MCP/Chrome checks and screenshot inspection. These are bounded checks, not full accessibility certification.

An agent may return an intervention object instead of a phase result. The harness validates and persists the question, records the call as waiting, and raises a distinct pause signal. The run enters needs_input. An answer is scoped to that run/question, retained as untrusted human-provided mission context and included in the retried phase. Completed steps remain cached. The two-attempt bound still applies: repeated clarification by the same phase can exhaust it. Pause controls are checked before each phase and do not terminate an in-flight model request.

QuickJS 0.31.0 runs inside WebAssembly, hosted by a fixed Node script. User-generated source is evaluated only in the guest VM. No host functions or module loader are exposed. Each check gets a fresh guest runtime; expected primitives are compared in the trusted Node host. The Python adapter passes JSON over stdin, uses a fixed command, scrubs credentials/NODE_OPTIONS from the subprocess environment, applies an outer timeout, and validates the returned envelope. Source/check hashes prevent evidence replay against changed content. No claims are made about browser behavior, third-party integrations, or correctness beyond the declared checks.

Execution failures enter the independent review context and cannot be overridden by a positive review. org_executions, org_interventions, org_controls and console_chats are additive tables. Readiness distinguishes dependency availability and live-provider configuration; fixture and live modes remain explicit. The user deferred live inference until they configure their key.

## Decision: hybrid organization runtime (0.12, 4 November 2026)

`assistance.py` persists employee-to-own-head requests, own-head decisions, head-to-head answers and attributed guidance. Help is a distinct response branch, never a completed artifact. Cached base steps keep immutable input hashes; `head_help` is recorded supplemental context for the resumed attempt. Two requests per step prevent advisory loops. Pending head clarification resumes the same assistance record.

`replanning.py` drains the current dependency wave and creates a linked child run after Director approval. Up to two revisions preserve the objective, original department scope, declared files, acceptance criteria, checks, capabilities, connector fingerprints and shared usage ledger. Concurrent approved workstreams are unioned. Prior files are explicitly bounded references. Human guidance/pause wins over a simultaneous revision; pending revision checkpoints survive resume. Pause, activity, file merging and effective-run lookup traverse both repair and plan edges. Same-team retasking requires a concrete broken dependency or approach correction. This is bounded replanning, not arbitrary organizational self-modification.

`retrieval.py` filters authorized candidates before hybrid BM25-style and local BGE cosine ranking. Approved department knowledge, same-agent/provider episodes and reviewed cards/lessons keep separate scopes. Content hashes invalidate derived vectors; overlapping chunks preserve later passages. The ONNX model is installed explicitly, runs locally and falls back visibly to keywords when unavailable. Embeddings retrieve references; they do not change model weights or prove improved outcomes.

Agent definition `role` remains an authorization/control class; `specialty`, responsibility, working method and quality checks describe distinct expertise. Version roles-v2.0 strengthens all 101 prompts without claiming 101 independent intelligences.

Provider JSON turns use SSE buffering, bounded frame/body sizes, complete termination validation and observed usage. No private reasoning is displayed or persisted as a progress hint. Output growth and deadline growth are separate from unlimited aggregate spending. Intake validation feedback is scoped to the current conversation hash, avoiding stale errors from prior turns. Generated Python AST/JSON checks never execute source. Declared HTML receives a real isolated browser smoke check when available, but no backend execution is inferred from it.

`source_archive.py` uses source allowlists, denies runtime state and symlink/reparse traversal, validates its ZIP and replaces it atomically. Distribution is separate from the live workspace; encrypted credentials are intentionally retained only in private live state.
