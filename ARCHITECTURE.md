# Collective 101 architecture

The living roadmap is [PROJECT_STATUS.md](PROJECT_STATUS.md). This document records implementation decisions and their consequences.

## Decision: inert Markdown presentation (3 November 2026)

`web/markdown.js` renders assistant messages and Markdown document Preview through local pinned Marked/DOMPurify browser bundles. Raw HTML is escaped before sanitization, the output uses an explicit tag/attribute allowlist, remote images become inert text and external links receive safe protocols/opener isolation. Sanitized fragments enter the DOM; raw content never enters innerHTML directly. User messages and exact Source views remain text nodes. Preview/Source tabs are keyboard-accessible; executable HTML websites retain their separate opaque-origin preview server. File hashes stay in persisted artifacts/API/audit records rather than a viewer details panel.

Successful chat serialization hides stale current errors without changing old stored evidence; new/successful turns clear the current error field. Failed runs and recorded diagnostics remain available in Activity. This presentation path makes no model request and never rewrites original message/file content.

## Decision: evaluated, bounded departmental execution (3 November 2026)

`effectiveness.py` adds additive evaluation run/trial/request/human-review tables and a single bounded evaluation worker, separate from the chat queue. `benchmarks.py` owns versioned case inputs, published criteria and independent deterministic graders. All identities appear in scorecards; only the representative cases currently provided can generate formal evidence. Runtime quality, provider errors, unavailable execution, human-pending work and fixture data stay distinct. Score groups are fingerprinted by provider/model/endpoint, role definitions, suite/harness and request settings; role and case snapshots preserve the tested inputs. Paired comparisons have equal per-trial admission ceilings within a shared batch meter and show actual usage. A stopped/restarted evaluation never silently resumes billable work. Confirmed UI starts, stopping and human reviews use the existing token/same-origin API protections.

New runtime tables store a per-run concurrency/memory policy. `runtime_core.run_dag` schedules dependency-ready trusted internal jobs in bounded waves, supplies immutable completed dependency snapshots and drains in-flight work before propagating a failed/pending-human boundary. The departmental engine separates begin/employee/report jobs, preserving head-only handoffs, own-department assignments, deterministic output paths, independent review and repair caps. Budget reservations stay transactional. Tool calls reserve a recorded dispatch under the database lock before action, closing a reproducible parallel cap race; interrupted dispatches cannot silently duplicate actions. Old runs default to serial and repairs inherit policy.

`learning.py` retains historical cards and adds structured proposed/reviewed/revoked/expiring lessons tied to the producing agent, model signature and source run. Only reviewed, relevant, unexpired lessons enter reference retrieval. Memory-disabled policy also removes memory-search grants. Evaluation memory arms share a frozen reviewed snapshot and do not train on their output. Existing Director improvement messages are surfaced as hypotheses, not accepted prompt edits or earned promotion. General prompt optimization and demonstrable held-out improvement remain separate work.

`execution_adapters.py` is a fixed-command boundary. The static browser runner uses the existing capability preview and opaque iframe, a fresh sandboxed Chromium context, local-origin request restrictions, bounded selectors/actions and Windows process-tree ownership. It gives agents observed interaction evidence without arbitrary navigation/host evaluation. Python/offline Node use fixed digest-pinned Docker profiles with explicit source-only staging and resource/authority limits. No image is pulled and no generated code falls back to a host interpreter. Current Docker absence blocks real container validation. Mission browser/runtime checks read persisted artifacts, hash inputs, cache results and override positive review on failure. The browser adapter is currently Windows-specific; general external browsing/build-dependent preview/hosting remain unavailable.

The legacy event engine is isolated in `legacy/runtime.py`; the public `runtime.py` facade preserves earlier imports and commands. The generic departmental engine is canonical. This is an incremental compatibility boundary with regression coverage, not a destructive schema/engine rewrite.

Meta structured responses now use documented schema-constrained JSON, while native legacy tools retain their wire protocol. Empty assistant answers are provider failures with usage; malformed text produces safe shape metadata and actionable contract feedback. The observed research failure had zero dispatched searches; the raw rejected answer was not saved, so its exact cause cannot be narrowed beyond pre-tool response parsing. [Meta JSON schema guidance](https://dev.meta.ai/docs/cookbook/structured-output), [Playwright browser sandbox option](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox), [Windows job ownership](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) and [Docker runtime controls](https://docs.docker.com/engine/containers/run/) document underlying mechanisms, not a certification of this application.

## Decision: local static preview and readable completions (3 November 2026)

`preview.py` manages a lazy loopback HTTP listener on an OS-assigned port distinct from the console. A same-origin, session-protected POST `/api/chats/{id}/preview` creates/reuses an unguessable chat capability URL, admitting only live-mode chats with saved HTML. The listener has no console APIs, credentials or filesystem routing. It reads the chat's merged saved artifacts through the console, preserves safe paths, allows only selected static text MIME types, bounds snapshots at 20 MiB and admits eight chat capabilities. Closing the console HTTP server also shuts the preview listener down. Links are process-local and expire on restart.

The preview shell opens in a new tab with no opener. It owns page selection, manual refresh, optional two-second revision polling and missing-page/connection feedback. Its iframe permits scripts without same-origin privileges. Artifact response CSP also enforces `sandbox allow-scripts`, including direct artifact navigation, with explicit local asset sources, blocked connections/frames/forms/base elements and restricted permissions. The shell uses only packaged trusted static assets. No arbitrary host code, dependency installation or deployment is performed. This is a browser static-content boundary, not a general OS/network/process resource sandbox; root-relative URLs and build-dependent/full-stack code remain unsupported. Policy is based on [CSP sandbox](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox) and [iframe sandbox behavior](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

`presentation.py` supplies `display_content` only for assistant messages matching a recorded completion. It maps each retained run/revision to its own summary, uses the Director's optional validated `user_summary` on accepted results, strips fingerprints/audit prefixes for historical fallback and emits truthful runtime failure/partial-file summaries. Original transcript content and retrospective evidence remain unchanged. Only role/content history is sent to intake, so presentation fields do not alter the recorded model conversation. The UI renders display text safely and keeps the file hash in a collapsed source detail disclosure.

## Decision: leadership-only interdepartmental communication

The Mission Director works through heads. Employees send results only to their head and receive assignments only from that head. Heads communicate with heads and the director. LeadershipBus enforces these edges in code and records each handoff with sender, recipient, kind and content. It rejects cross-department employee messages, employee-to-director bypass, and direct colleague conversations, including within a department. This keeps the first implementation's collaboration explicitly head-mediated.

The council passes leadership-authored proposals. A head collects employee outputs and forwards a department report plus published artifacts. The Assurance head delegates an independent review to an employee who did not produce any mission artifact. Review results return through the Assurance head to the director. Employees are not given a global conversation inbox.

## Department-led lifecycle

`ready -> running -> reviewed | blocked`

1. Validate a generic mission contract: objective, inputs, constraints, acceptance criteria, allowed capabilities and optional deterministic artifact checks.
2. Intake supplies a department shortlist (legacy JSON without one defaults to all heads). Ask those heads and transitively requested dependency heads whether they can contribute; require a justified contribution or decline. A contributing head proposes up to six owned tasks, employee assignments, required capabilities, output paths and dependencies.
3. Run one council round. Heads see peer proposals and revise or retain their scope to avoid duplication and declare dependencies.
4. The director selects a useful dependency-closed subset. Validate both department and intra-department DAGs.
5. Execute selected departments in dependency order. Heads brief their employees; each employee receives its task, own task dependencies and head-forwarded upstream reports.
6. The drafting harness invokes each assigned employee. It validates exact declared output files, records artifact provenance and hashes, and returns results to the head. Missing capabilities or blocked dependencies produce explicit blocked outcomes.
7. Heads aggregate progress, blockers and improvement ideas and publish reports to other participating heads and the director.
8. The Assurance head chooses an independent reviewer. Require explicit coverage of every original acceptance criterion. Run deterministic file existence/substring checks separately; a positive model verdict cannot override their failures or runtime blockers.
9. The director synthesizes the outcome and proposes bounded improvements with a responsible department, supporting observation and measurement. Proposals are recorded and routed to heads; they are not auto-applied policy changes.
10. Store recent reviewed agent episodes for later same-agent, same-provider recall. Fixture and live memories cannot mix through this path.

Chat consults only shortlisted/dependency heads. Each consulted head has an assessment and council turn; a council request for an unconsulted department fails explicitly rather than silently widening the team. Legacy JSON without a shortlist retains all-head consultation. Department execution is sequential; no efficiency or scalability claim follows from this design.

## Persistence, resources and recovery

The original Store provides SQLite transactions. New `org_runs`, `org_calls`, `org_messages`, `org_artifacts`, and `org_experience` tables are additive and do not migrate or overwrite original event missions.

A run snapshots the mission and all agent definitions. Provider mode, model and endpoint must match on resume. Every phase reserves a call atomically, records its inputs, and validates its JSON response before caching it. Cached results are reused only when the agent/context hash matches. A phase has at most two failed/intervention attempts and four tool requests within an eight-call loop bound. A shared org_budgets record charges intake and mission provider requests before dispatch. UTF-8 input bytes plus a 4096 output allowance are charged as conservative token admission units. Failed/uncertain requests keep their reservation; provider-reported usage is recorded separately. No exact tokenizer or monetary billing ceiling is claimed.

CLI commands share the existing workspace lock. This is a single-process design; calling the library concurrently outside the CLI is not a supported scheduler. A process interruption between a provider response and its local commit may repeat that request on resume. No exactly-once provider guarantee is claimed. Source-code changes are not frozen with runs; only agent definitions and context are.

Message keys make leadership handoffs immutable on replay. Artifacts keep producer, task, path, content and SHA-256. Completed reviewed missions return without additional calls. Blocked results remain inspectable; resume reuses cached phases and does not invent new scope or refill exhausted attempts. General revisions and reviewer-driven rework rounds are future work.

Memory ranks up to 100 prior reviewed records for the same agent/provider by lexical overlap with the mission and task, with recency as a tie-breaker; it supplies at most three. An explicit memory_search tool can query these episodes. Per-step memories are frozen from the first recorded input when resuming. Approved long-term reference files live under knowledge/shared and knowledge/<department>, accessed only through scoped read/search tools. Its content is untrusted historical context, not a policy update. Retrospectives are improvement hypotheses, not measured learning or automatic responsibility changes.

## Implemented console and intervention boundaries

`web_server.py` serves a Bootstrap 5.3.8 UI and a small JSON API from loopback. Static routes are allowlisted; generated artifacts are returned as JSON/text, never served as executable pages. An agent may return an intervention object instead of a phase result. The harness validates and persists the question, records the call as waiting, and raises a distinct pause signal. The run enters needs_input. An answer is scoped to that run/question, retained as untrusted human-provided mission context and included in the retried phase. Completed steps remain cached. The two-attempt bound still applies: repeated clarification by the same phase can exhaust it. Pause controls are checked before each phase and do not terminate an in-flight model request.

QuickJS 0.31.0 runs inside WebAssembly, hosted by a fixed Node script. User-generated source is evaluated only in the guest VM. No host functions or module loader are exposed. Source/check hashes prevent evidence replay against changed content. No claims are made about browser behavior, third-party integrations, or correctness beyond the declared checks.

Execution failures enter the independent review context and cannot be overridden by a positive review. org_executions, org_interventions, org_controls and console_chats are additive tables.
