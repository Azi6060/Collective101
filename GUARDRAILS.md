# Guardrails and operational boundaries

UI thumbnail addition (4 November 2026): authenticated same-origin operator capture accepts only a validated saved HTML artifact. It freezes at most 32 files/1 MiB, serves them on a separate opaque capability origin, disables page JavaScript/service workers/downloads, and blocks requests outside the exact frozen artifact prefix. A fixed trusted screenshot runner uses the existing fresh Chromium sandbox and Windows owned-process-tree/filtered-environment bounds (one capture, 22 s, 1 GiB); PNG output is at most 1 MiB with eight revision-specific in-memory cache entries. No arbitrary URL/path/evaluate, personal profile, console credentials, model call or host execution fallback is exposed. Working drafts capture only by explicit user action; automatic thumbnails wait for a stable outcome and visibility. Static pictures are presentation, not acceptance/competence/deployment evidence. Existing agent grants, mission budgets, review prerequisites and interactive Preview isolation are unchanged.

Policy reviewed: 2 November 2026 (Asia/Kuala_Lumpur). This is a policy/risk record; PROJECT_STATUS.md owns the roadmap.

| Risk or edge case | Enforced behavior | Limits |
| --- | --- | --- |
| Greeting accidentally launches the organization | Head of Distribution receives the live message and chooses reply/clarify/mission | No local greeting or length rule; live decision quality still needs evaluation |
| Ambiguous or high-stakes intent | Agent-authored contextual intervention, persisted answer and bounded resume | No keyword-triggered questions; model judgement needs live domain evaluation |
| Wrong department or ownership | Validated shortlist, dependency closure, employee-to-own-head reporting and leadership-only cross-department bus | One council round; no general mid-run help/replanning |
| Prompt injection from documents, web or memory | Untrusted source labeling plus runtime tool scopes, phase permissions and immutable criteria | Instructions alone cannot guarantee semantic resistance; live adversarial evaluations remain necessary |
| Agent asks for more authority | Broker intersects identity, mission and head assignment; leadership may use knowledge/memory and enabled read-only connectors within mission permission | Agents cannot install tools, connect accounts or grant themselves permissions |
| Cross-department/private file access | Dedicated shared/own-department text folders; relative paths, extension/size bounds, traversal and symlink/junction rejection | Local knowledge is deliberately trusted for ingestion, not for instructions. No hostile multi-user filesystem race guarantee |
| External query discloses data | Operator enables a connector for the organization; agents work within that purpose and may ask contextual human guidance | No automatic per-query question. Model disclosure judgement requires evaluation; retrieved knowledge also goes to the configured model |
| Unavailable tools or invented evidence | Explicit denied/unconfigured/unavailable/failed results; essential access or success evidence missing blocks task; optional failures reach the head | Retrieved snippets are not verified full-page research or general factual correctness |
| Infinite model/tool loops or runaway spend | Shared intake+mission call and token-admission ledger; four tools per phase, forty recorded tool requests per mission; bounded phase retries | Admission units are conservative estimates, not invoice tokens. No dollar cap or tool-service pricing calculation |
| Model/provider outage | No silent fixture fallback; requests are recorded, retries bounded, uncertain reservations retained | Exactly-once external requests are not guaranteed across process death |
| Unsafe generated code | QuickJS/WebAssembly with no host APIs, plus SELECT-only in-memory SQL; bounded memory/query sizes, instructions and execution time | Not a container, DOM/browser or general OS sandbox |
| False success or self-review | Non-producing Assurance reviewer, original criterion coverage, deterministic checks and blockers override positive prose | Narrow checks cannot establish universal correctness; fixture reviews are scripted |
| Misleading memory/promotion | Same-identity/provider reviewed episodes, provenance, bounded retrieval, immutable roles and permissions | Recall is not training; successful fixture execution is not competence or promotion evidence |
| Local web attacks | Loopback host validation, session token, same-origin writes, CSP, textContent, static route allowlist | Single-user local service; not authenticated multi-user hosting |
| External connector actions | Remote MCP tools must declare read-only and be selected by the user; write/unknown tools cannot be enabled | Annotations are server claims, not enforcement inside a remote service. Trust/configure the server appropriately; no write adapter or arbitrary shell is exposed |

## Human guidance

Generated-site previews (3 November): a session/origin-protected console action opens a separate loopback origin with a per-chat unguessable URL. Only that chat's validated saved text artifacts are served, bounded at 20 MiB; there is no filesystem fallback, directory listing, console API, model credential, shell or package installation. The iframe and artifact response CSP use an opaque-origin sandbox with scripts allowed and no same-origin/popups/forms/top-navigation grants; connections and external assets are restricted. Normal UI preview opening severs the opener. Browser content is still untrusted, and this boundary is not a CPU/memory/container guarantee. Do not claim generated apps were browser-tested merely because a human preview exists. Build-dependent/full-stack runtimes and root-relative asset mapping remain future work. Preview bearer URLs are private local links and are discarded on restart; eight chat previews are admitted per console process.

User-facing completions are presentation only. Director prose cannot override runtime acceptance. Failed checks show failure and saved partial work even if a model claims ready. Hashes and internal audit framing are removed from the chat display, while original transcript, retrospective, artifact fingerprints and review evidence remain intact. No historical result is silently rerun or rewritten through a paid provider.

Every new clarification question is authored by a model: the Head of Distribution during intake, or the requesting head/employee during execution. The runtime validates the structured question, records agent identity/reason, pauses and resumes with a bound answer. Prompt length, keywords and tool names do not create questions. Missing credentials produce configuration errors, not conversational interventions. Permission and budget checks remain deterministic and cannot be overridden by model text.

The 2 November user correction supersedes the earlier keyword preflight and fixed web-query approval behavior. Existing historical intervention records remain on disk; newly created chat sessions are live-only. No automatic weakening of permissions follows from an answer.

## Connector boundaries

Credentials use Windows user-bound DPAPI encryption. HTTP responses expose presence only, never the credential or encrypted blob. Remote results/metadata have reflected credentials redacted and remain untrusted data. Connections are restricted to configured endpoints; MCP DNS addresses are validated and the socket is pinned, TLS uses the original hostname, redirects are not followed, and time/size limits apply. Loopback HTTP requires explicit local-server configuration. OAuth, stdio launchers, server-initiated sampling/elicitation, and write operations are unsupported.

Selected tools, enabled state and mission/task permissions are rechecked per call. All registered identities are eligible for connected tools; no department-specific connector grants remain. Mission fingerprints bind connector configuration; changing it requires a new mission rather than silently widening prior permission. Disconnecting prevents further external calls. Cached historical evidence is still inspectable. Schema validation beyond required fields is performed by the remote MCP server; the client does not fetch schema references.

## Safe fallback

Source-delivery contracts require declared files/owners before new live builds; website plans require Engineering-owned HTML. Model approval cannot replace missing source. Soft head report concerns do not block all downstream work; one bounded final head reconciliation can resolve fulfilled handoffs, while actual failed task dependencies and capability denials remain authoritative. Repairable quality/dependency blockers may reach correction rounds; essential unavailable capabilities do not trigger blind retries.

Source export reads only persisted artifacts belonging to the chat and its retained run/revision history. ZIPs reject traversal, absolute/Windows paths, case collisions, file/directory prefix collisions and reserved root metadata names, retain a 20 MiB bound, and require the console session. No credentials, database files or arbitrary host paths are exported. Source views use textContent. Assistant Markdown and document Preview use Marked plus DOMPurify with a restricted tag/attribute allowlist; raw HTML is escaped, images are inert text, executable/style/SVG/form attributes are unavailable, and links allow only HTTP/HTTPS/mailto with a severed opener/referrer. No untrusted content reaches innerHTML directly. File fingerprints remain internal rather than displayed in a details panel. Line-diff caching is bounded. New frontend submissions are disabled if the connected server lacks the chat-workspace capability.

Per-request model input is independently bounded to 262,144 UTF-8 bytes; intake history windows retain at most 96,000 bytes. Full stored history is not deleted. The newest message remains in the request, with a bounded initial-intent excerpt when both extremes cannot fit. Window omissions and truncated prior-source excerpts are disclosed as data limits. Input bytes are not claimed as exact provider token counts. Temperature accepts only finite numeric values 0–2; it cannot grant tools, enlarge budgets or bypass delivery validation.

Model request recovery has independent bounded categories: three provider/transport failures, two truncated responses, two invalid agent outputs and twelve total requests per step. Authentication and other non-retryable provider errors stop immediately. Each network attempt is recorded and reserves the actual output allowance plus conservative input units before dispatch; increasing the output allowance never increases the mission's call/token caps. Reported usage survives rejected truncated/malformed results, and uncertain calls retain reservations. Retry options/error categories persist across resume. Partial JSON/files cannot be accepted as artifacts. Operator request settings are bounded at 32,768 generation tokens and 300 seconds; models cannot modify them. Connector source metadata exposes credential presence/provenance, never key material, and does not prove successful authentication.

Use available supplied evidence when an optional capability is missing, label the limitation and avoid claiming external work. Block work whose acceptance depends on missing access/evidence. Do not replace live failures with fixtures or use uncertain memory as fresh evidence. Do not automatically relax criteria or increase budgets.

## Revising guardrails

User-authorized budget increase (3 November): the chat default/maximum is now 10,000,000 admission units, retaining 160 total model calls and all per-step/context/output limits. The exhausted cafe chat's cap may be explicitly raised without deleting spent reservations or reported usage. Other existing ledgers keep their operator-selected limits; evaluation batches remain capped at 2,000,000. Raising a cap never automatically executes or replays work.

Keep policy changes reviewable in this repository. For each observed failure: retain a sanitized regression case, identify the violated invariant, add the failing test, change the narrowest relevant runtime rule, run affected checks and then the full suite, and record verification and residual limits in PROJECT_STATUS.md. Evaluate false-positive interruptions as well as missed risks. Agents may propose changes with evidence and a measurement; they cannot apply their own security changes, promotions or budget increases.

Before adding a write-capable API, specify allowed identities, account/data scope, read versus write operations, argument validation, idempotency, rate/cost caps, audit events, failure behavior and an approval-bound action payload. Connect only the account needed for the task. No placeholder connector should be presented as working access.

The connector catalog contains Coming soon service previews with no setup/account action. They grant no tool access. Existing saved connector department scopes are migrated to the whole organization without changing encrypted credentials. The changed scope invalidates old MCP mission fingerprints. Global eligibility does not remove mission/tool budgets, employee task grants, local knowledge isolation, or the ban on write-capable connectors.

## Revisions, knowledge and measured responsibility

### Saved-work UI boundaries (5 November 2026)

The user's finishing checklist authorizes saved-title/filename search, presentation-only renaming, tab draft recovery and upload feedback. Search reads bounded metadata from live-mode saved chats, including prior/repaired saved filenames; it does not read host files, file contents, credentials or unused uploads. Rename writes a separate title record and cannot rewrite transcripts, evidence, original mission criteria, permissions or budgets. All endpoints keep existing same-origin/token/account authorization; name writes retain human-operator audit metadata.

Draft recovery stores only bounded user text, completed attachment IDs and non-secret request fingerprints/IDs in account-scoped tab sessionStorage, with memory fallback and explicit unavailable feedback. It is not encrypted/private-tenant storage or an authentication mechanism. Twenty drafts/24-hour expiry, account transitions and explicit discard bound retention. Raw file bytes, recordings, passwords, model keys and auth-session credentials never enter this cache. Attachment recovery enforces pending ownership/expiry and shared bound-chat access. A failed metadata recovery blocks sending until explicit retry/discard; unchanged failed sends reuse the existing backend idempotency key rather than dispatching automatically. Edited input/settings may form a new request; no failed paid work is silently relaunched.

Upload progress measures browser transfer, followed by a distinct server-check state. Cancellation aborts the client reader/request but is not transactional rollback; server-side unused drafts retain existing expiry. Retry is explicit and completed uploads survive unrelated failures. Failed/cancelled queue items block Send until retried or removed. File selections remain only in memory; no automatic retry, new execution capability, connector adapter or external-account service is introduced. Manual physical-device/voice/accessibility review belongs to the teammate; automated browser fixtures remain clearly labeled.

### Local operator accounts and chat uploads (5 November 2026)

The user's account/upload/voice request authorizes these local console features. Local owner/member accounts identify human workspace operators, separately from the 101 organization roles and executable agent permissions. This is one shared workspace: authenticated members share its chats, files, connectors and controls. Accounts do not create private tenants or grant an agent additional tools. Before the first account, the existing loopback guest workspace remains available; first-owner creation closes private APIs to unsigned clients. Later registration requires an owner-created, single-use, 24-hour invitation. Only the owner may create invitations; users edit only their own name/password. Password changes revoke existing sessions. Account endpoints validate names/usernames/password bounds, use parameterized SQLite queries, scrypt with independent salts, constant-time password comparison, bounded login attempts and secret-free audit events. Opaque sessions are stored as hashes, expire after twelve hours, and use host-only HttpOnly/SameSite=Strict cookies; no identity token enters localStorage or model prompts. The console's existing token/Host/Origin checks remain mandatory. The Secure cookie flag requires HTTPS and is intentionally absent only for this server's existing HTTP loopback binding; this is not a public hosting authentication design. No OAuth, email verification/recovery or cross-device service is implied.

Public startup exposes only the app shell and selected static organization identifiers/department names. Private API reads/writes require membership once accounts exist. Generated-site preview capabilities are scoped to an authenticated session and invalid after expiry/logout/password revocation; first-owner setup revokes former guest preview links. Existing source-only exports and isolated Preview boundaries remain. Signing out revokes access, not already authorized running work; it does not start new work or alter mission pause controls.

Uploads are operator-supplied data, never policy or execution permission. API writes accept only validated names, bounded base64 content and allowlisted text/code, DOCX, PDF, image or video formats; binary MIME signatures are checked. No upload path is interpreted as a host path. Originals are inert SQLite blobs with opaque IDs and content hashes, downloadable only through the authorized console. Draft files belong to their uploading operator; bound files belong to the shared chat. Removal only deletes the operator's unused draft upload. Identical pending uploads deduplicate, original chat bindings are immutable, and request-ID replay checks include attachment IDs. Follow-up message request IDs prevent paid duplicate dispatch on retries. No upload launches a program, shell, parser extension, external resource fetch or automatic model call. DOCX extraction has archive/XML expansion bounds and rejects entity declarations. This is not malware scanning or comprehensive media codec validation.

Limits: six files/50 MiB per message; 25 MiB/video, 10 MiB/image, 2 MiB/text or DOCX; eight pending files per operator; 256 MiB/2,048 stored files per workspace. Two concurrent upload slots and a thirty-second read deadline bound ingestion. Unbound uploads expire after 24 hours; bound originals remain saved. Models receive a disclosed window of the newest eight references and bounded text excerpts (up to 14,000 JSON characters), charged through existing context/admission limits. Binary images/videos/PDFs remain reference-only with the current text provider: never claim they were watched, transcribed or analysed. Essential unavailable evidence must reach agent-authored clarification or a blocked result. The UI may show local image/video previews without treating them as verification.

Voice input starts only after the user elects it and permits the browser microphone; the UI discloses that browser speech services may process audio remotely. Recognition writes an editable draft, never sends automatically, and stops on navigation/recording errors. Read-aloud is explicit, bounded and cancellable. Unsupported browsers retain typing/uploads with an honest unavailable state. Development uses mocked speech events, never covert microphone capture or paid inference. Both new brand/dashboard decoration and existing motion obey app/device reduction and suspension rules.

The user's 5 November recording/waveform request authorizes ephemeral local audio capture and replay. Raw recordings stay only in tab memory as owned blob URLs, capped at two minutes/8 MiB; they are never automatically attached, uploaded, logged, persisted or sent to agents. Only optional browser transcription may use the disclosed browser speech service. Capture is opt-in and stops on stop/cancel, device failure, navigation, hidden tab or the cap. Generation guards stop streams granted after cancellation. Send, chat switch, deletion and page exit discard the local clip and revoke its URL. Waveform amplitudes are measured microphone data and playback progress follows the recorded audio, not inferred agent activity or fabricated TTS levels. Developer Chrome tests may opt into a generated synthetic microphone only with disposable isolated state away from port8765; they never use a personal microphone or automatically invoke remote transcription.

One review-driven repair round is enabled by default; the mission may set zero to two. Original objective, criteria and capabilities remain unchanged. Separate run records preserve attempt evidence; root model/token/tool budgets, root pause and active-revision interventions persist across resume. Missing capabilities block instead of causing automatic retries. Changed connector fingerprints prevent revision calls. Bounded previous-artifact excerpts are untrusted data; a revision requires fresh execution evidence and independent review.

User document ingestion only writes bounded, hash-named UTF-8 documents under approved shared knowledge; it cannot import executable files or overwrite differing content. Consolidated memory remains same-agent/provider, provenance-linked, bounded and snapshotted; source instructions never become policy. Responsibility recommendations require distinct live objectives, independent acceptance and deterministic output checks beyond existence. They can decline with repeated failures, but never widen permissions, budgets or leadership roles. Scores do not prove causality or model learning.

SQL uses SQLite authorization, instruction/time/size limits, an in-memory supplied dataset and a function allowlist; attachments, system-table reads, writes, extension loading and pragmas are denied. No arbitrary Python/shell is exposed. Static HTML checks do not execute scripts or load resources and do not replace real-browser accessibility review. See [Python sqlite3 authorization and progress APIs](https://docs.python.org/3/library/sqlite3.html) for the underlying controls.

Chat activity hints expose only registered agent/phase/tool labels, not hidden model reasoning or tool arguments. Hints are separate from transcript messages; status-only polling does not rebuild the conversation log.
